# Inkwright (id: inkwright)

Obsidian plugin: edit and play ink stories (inkjs), Chinese/English UI, desktop + mobile.

## Commands
- `npm test` — vitest (Node). macOS has no `timeout`; wrap long runs with `perl -e 'alarm 90; exec @ARGV' npx vitest run`.
- `npm run check-ink -- <folder>` — compile + auto-play every main .ink under a folder (INCLUDEd chapters skipped); use it on vault content and tutorial examples. `--all` plays every branch (breadth-first, `src/play/explore.ts`) and lists the endings; `--lang zh|en` for bilingual stories. A story with a `game.md` next to it is explored in game mode, once per character, walking success and failure of every check (paths show `[insight✗]`); failed checks that change nothing are warnings. States reached before are not expanded again (`stateInfo` in explore.ts; turn counters, seed and last random are left out, so futures that differ only by a RANDOM still to come count as one) and a spot (the same choices offered) is expanded from at most `--states-per-spot N` states (default 10), so a game whose resources differ on every path stays finite; `--max-steps N` (default 20000) still bounds the walk. `--novelty` replaces the spot cap: a state is played on only when something about it is new at its spot — a variable that can change what happens next (`src/play/relevance.ts` reads the story JSON for variables used in conditions, choice conditions, arguments or fed into such variables; printed-only and self-updating ones are ignored) stands differently to the constants it is compared with than any value seen there (`shape.thresholds`), or is beyond the lowest/highest seen there with a threshold still ahead in that direction (a counter past its last threshold can grow without being new; one compared with no constant is new at every extreme), a flag/string/list has an unseen value, or a sequence's count is new. Novelty mode walks depth-first, so a run to an extreme widens the envelopes early. Long games finish (dorm-302: ~100 s per language) and the paths that wear a resource down to a threshold are kept; combinations seen piecewise are not replayed, so it is a search strategy, not a proof. `--novelty 2` makes the same judgement again among the states that share each gate's value (`shape.gates`: flags, strings and numbers read by choice conditions, a number as it stands to its constants; lists are left out, an inventory would be a context per combination), so a flag or a resource that is old at the spot can still be new among the states where a door is already open; it recovers a branch two things must agree on (dorm-302: the write-back of a cleared name, which needs the stairs visited and hours left) at about four times the cost (dorm-302: 100k choices and ~13 min per language against 26k and ~4 min; needs `--max-steps 200000`). Pairing every fact, or making a context per inventory, blew the budget or took an hour. Use it locally; keep CI on `--novelty`. Every `--all` run also reports coverage (knots/stitches/labels and choice points never reached or taken), knots statically unreachable (from the compile graph) and, in game mode, resources the story pushed outside their `min..max` (`checks.outOfRange`: the engine clamps them after the step and keeps the overshoot). `--random N [--seed S]` plays N runs choosing at random with real dice (`src/play/simulate.ts`) and reports the odds of each ending, the spread of choices per run and where each resource ends up (min/mean/max, p10/p50/p90, runs ending at min/max): for balancing, and it finds paths the exhaustive walk never gets to. In game mode the engine keeps every roll of a run (`keepRolls: Infinity`) and `Tally` counts them at its end: rows per table (`DiceRecord.table.row` = the row index; `none` = totals no row covers), cards per deck (a draw from an empty pile rolls nothing, so it is not counted), checks per skill + difficulty with the success share.
- `npm run gen-engine -- <main.ink> [--check]` — writes the game's engine ink (`_engine.ink`, or `engineFile`) from the note next to the story, `from:` tables/decks/canvas resolved from disk (`scripts/game-note.ts`: `diskSource`, `loadGameConfig`, shared with check-ink); `--check` only compares and exits 1 when the committed file is stale (for a game repo's CI).
- `npm run export-web -- <main.ink> <out.html> [--lang zh|en] [--id key]` — the web export from the command line (used by the public games repo luoxin9510/ink-games). A `game.md` next to the story makes the page a game (engine embedded).
- `npm run build` — tsc + esbuild → `main.js`. `OBSIDIAN_PLUGIN_DIR=<vault>/.obsidian/plugins/inkwright npm run build` builds into a vault.
- Game vault: `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/ink-games` (iCloud, used on phone too).

## Verify in Obsidian (Obsidian CLI, `/opt/homebrew/bin/obsidian`)
Always pass `vault=ink-games`. Never quit/restart the whole app: other sessions may be using other vaults (e.g. atlas-vtt).
- Deploy + reload: build with `OBSIDIAN_PLUGIN_DIR` (above), then `obsidian vault=ink-games plugin:reload id=inkwright`.
- Drive it: `open path="游戏/雨夜来客/main.ink"`, `command id=inkwright:open-play` (also `inkwright:lock-main`, `inkwright:unlock-main`); `commands` lists ids.
- Inspect: `dev:errors` (captured errors), `dev:console`, `dev:screenshot path=<png>` (2940x1696; crop with `sips -c H W --cropOffset Y X`), `dev:dom`, `eval code='...'` (e.g. `app.plugins.plugins.inkwright`), `dev:mobile` (toggle mobile emulation).
- `reload` reloads only the vault; `plugins:enabled`, `plugin id=inkwright` show state.

## Agent API (`src/api.ts`)
`app.plugins.plugins.inkwright.api` — call via `obsidian vault=ink-games eval code='...api.<method>(...).then(JSON.stringify)'`; `api.help()` prints usage.
Headless: `compile(path)`, `graph(path)` (nodes/edges/unreachable), `play(path, {from?, choices?})` (choices by index or text) → transcript, variables, visits, errors; `explore(path, {language?})` → every ending reached and runtime errors. Visible panel: `open`, `panel`, `choose`, `restart`, `startAt`, `back`, `save`, `saves`, `load`, `deleteSave` (saves live in plugin data per main story). Export: `exportWeb(path?)` → standalone `.html` next to the story; `journal()` → the panel's run as a markdown note. Bilingual stories (`VAR 语言`/`VAR lang`, text via `{双("中文", "English")}`): `play(path, {language})`, panel `language(lang)`; switching replays the run (`PlaySession.setLanguage`), `src/compile/bilingual.ts` warns about bare text.
The game vault has its own `CLAUDE.md` telling agents how to playtest; keep it in sync when the API changes.

## Game mode
PRD: `docs/game-engine-prd.md` — TTRPG-style rules engine on top of Inkwright (2d6 checks on choice tags, 5 skills as inner voices, fear resource, 4 selectable PCs, state stays in ink). Read it before touching `src/game/`. Example game: vault `试玩沙盒/游戏模式/` (`游戏.md` + `_引擎.ink` + `main.ink`).
- A game is a folder whose main story sits next to a `game.md` (or `游戏.md`) note; its frontmatter is the `GameConfig` (`src/game/obsidian.ts`: `findGameNote`, `loadGameConfig` via the metadata cache → `readConfig` in config.ts checks the shape, then `validateConfig` the rules). Problems are data (`ConfigProblem` = code + args) worded by `T().configProblem`, shown as warning diagnostics; the note is a dependency, so edits reload (also on `metadataCache` "changed").
- `src/game/dice.ts` — dice systems (`sum` = NdX + skill vs difficulty with natural crits and a partial band; `rollUnder` = d100 CoC style), `resolve` (rng injectable, `force` a band for explorers), `chance` by enumeration. Five bands 0–4 shared by every system.
- `src/game/config.ts` — `GameConfig` (rules, skills, resources, companion resources, characters, modifier rules, ink names), check/voice tag parsing (`* [text #check:skill:difficulty[:red]]`, difficulty optional for `rollUnder`; `#voice:skill`), `collectModifiers` from story state, `validateConfig`. Ids are code (English); player-facing names are `LocalizedText` (`{ zh, en }`, `localize`). Ink name presets: `ink: en` (default) / `ink: zh`; `languages: [zh, en]` makes the generated ink declare the `lang` VAR and `t(zh, en)`. A character with `playable: false` is a companion only (`playableCharacters`): never in the picker (no picker when one character is playable), not played by `check-ink --all`, but it still gets companion variables.
- `src/game/inkgen.ts` — `generateInk(config)` → the `_engine.ink` a game INCLUDEs: VARs, character LIST, `pick_character(who)` preset loader, `skill_level(name)`, `t()` for bilingual games, and an ink fallback for the EXTERNAL check so stories run without the engine. Stories call `check("skill", difficulty)` with the id as a string (the engine logs the roll under that skill).
- `src/game/engine.ts` — `GameEngine`: binds the EXTERNAL check on each new Story (`PlaySession`'s `setup` hook), loads the character preset, `describeChoice`/`voiceOf`/`hud()`, keeps the dice log. The story's variables are the only state: the engine writes only the preset, a per-run dice seed and a roll counter, and the n-th check's faces are a hash of (seed, n), so back/load/language replay roll the same dice (`seededDice` in dice.ts).
- `src/views/PlayView.ts` renders the character picker, HUD, check odds on choice buttons, voice paragraphs and the dice log; `api.panel().game` and `api.character(id)` expose the same. The latest choice is drawn as a rule carrying its text (`.inkwright-turn`) where the text it produced begins (`PlaySession.lastChoice` / `PlayState.chosen`; only the latest, moves on each choice, gone after undo, restart or load), and the new text scrolls to it. Layout: `render()` puts the status (HUD, map, dungeon, dice log) in `.inkwright-side` and everything else in `.inkwright-main` inside `.inkwright-stage`; `.inkwright-play` is a size container and `@container (min-width: 720px)` lays a split stage out in two columns (side sticky, own scroll); the bar's fold button hides the side (`sideHidden`, per view) and its move button calls `controller.movePlay` (`openPlay("main" | "side")` in main.ts detaches the leaf and reopens it in a main-area tab or the right sidebar; command `open-play-main`). The top bar can be pinned (`pinBar` setting; the pin button on the bar and the settings tab toggle it): `.inkwright-bar-pinned` is sticky inside the view.
- Resources live in `min..max`: `GameEngine.setup` observes every resource variable (the character's and each character's companion ones, `fear_yi`) and clamps it once the step is done (inkjs notifies observers after a Continue); the overshoot is kept in `takeOverflows()` for the explorer and the random player, so a `~ fear += 30` past the top is a warning in `check-ink`, not a bug in the HUD.
- Engine code must stay game-agnostic: skills, resources, characters and names come from the config, never from literals in `src/`.
- Command `inkwright:generate-engine` / `api.generateEngine(path?)` writes the engine file (`engineFile`, default `_engine.ink`) from the note; the panel warns when the story lacks the INCLUDE or the file no longer matches the note.
- Keep ids and ink names English and localize only player-facing text; no separate translation tables.
- Items: `items` in the config (`ItemDef`: id, name, desc, `modifiers` = skill bonuses while carried) and `items` on a character (starting items). The generated ink declares `LIST items` and `VAR inv = ()` (names from `InkNames.items/inventory`), and `pick_character` sets the inventory; the story itself picks things up (`~ inv += knife`) and tests them (`{inv ? knife: …}`). `#needs:<item>` on a choice shows a badge and locks the button while the item is not carried (`GameEngine.needsOf/canChoose`; the controller, the web player and the explorer all refuse it; an unknown item is never satisfied and `check-ink --all` warns; a spot where every choice is locked is reported as stuck, `checks.lockedOut`). `hud().items` lists what is carried; `collectModifiers` adds carried items' bonuses.
- Effects: a line tagged `#fx:shake|flash|dark|pulse` (`FX`/`fxOf` in config.ts, a fixed vocabulary) plays that effect on the story text when the line first appears after a clicked choice, in the panel and the web page; nothing plays on back, load, resume or re-render, and `prefers-reduced-motion` turns it off. A check's roll shows as a card in the text (skill, faces, sum, outcome; faces tumble briefly): `RollRecord.turn` is the story turn the check was rolled in, `PlaySession.turns` gives the turn per paragraph (null for text restored from a save), and the panel puts the card before the first paragraph of that turn; the web player logs the turn on each entry and puts the card under the chosen line.
- `exploreStory(story, { game, character, bands })` forces every check through the engine's `force` hook: success first, then a sibling move per other band, so both sides of each check are played (a check met before the first choice is played as success only); `checks.noConsequence` lists failed checks after which no variable and no choice changed (text-only or visit-count-only changes do not count). `api.explore` picks the game config up automatically; `check-ink --all` parses the note with `yaml` (CLI only).
- Web export (M4): `buildWebPage({ game, engine })` embeds the config and the engine bundle (`virtual:game-engine` = `scripts/engine-bundle.mjs` building `src/game/browser.ts` into the global `InkwrightGame`; same plugin in esbuild.config.mjs and vitest.config.ts, and export-web builds it at run time). The page's player then has a character picker, HUD, check odds on choices, voice paragraphs and a dice log; `engine.start(story, character)` re-seeds after `ResetState`. `pick_character` takes the id as a string, so the engine needs no inkjs import.
- `api.explore` takes `novelty`, returns `coverage` and `checks.outOfRange`; `api.simulate(path, {runs, seed, character})` is the random player. Both take the game config from the note next to the story.
- Next: the first slice script (M3).
- Tabletop PRD: `docs/tabletop-prd.md` — solo TTRPG / board-game support on top of game mode: five primitives (free rolls, random tables, decks, `#input`, play log to a note), what qualifies, the order to build them in. Read it before adding any of those.
- Tabletop slice 1, dice and tables: `src/game/dice.ts` parses and rolls formulas (`parseFormula`, `rollFormula`; `d66` is two d6 read as tens and units); `src/game/tables.ts` is the table logic (ranges, the dice given or inferred, `rowAt`, `tableProblems` for gaps/overlaps/bad dice, `rowsFromMarkdown` for a note's first markdown table, `resolveTables` fills `from:` tables in and lists the notes read). The engine binds one more EXTERNAL, `roll_dice(formula, label)`, on the check's seed and roll counter; `roll(formula)`, `table_roll`, `table_text`, `table_id` and `table(name)` are generated ink: the lookups are plain ink, so a story reads the same row without the engine (the fallback `roll_dice` returns each table's average, 1 for other dice). `engine.rolls` is `CheckRecord | DiceRecord` (`kind`); the panel, the web player and the journal render both kinds of card. The explorer gives the engine a fixed rng, so table rolls repeat between walks; the config's `from:` notes are compile dependencies (`GameNoteRead.files`), and `main.ts` resolves them wherever it loads a config (`resolveConfig`; `gameConfigFor` is async; `check-ink` reads them from disk). Formulas may explode (`d6!`, `DiceFormula.explode`: a top face rolls another die, faces appended, at most 20 extra; `averageFormula` uses the exploding mean). Table ranges may be open (`6+`, `≤0`/`<=0`: `Range` with ±Infinity; `tableProblems` clamps them to the dice span, the generated lookup treats an open top as the last row). Journal: `src/play/journal.ts` (`renderJournal`, pure) and `writeJournal()` in main.ts (command `write-journal`, `api.journal()`), path from the note's `journal.path`.
- Tabletop slice 2, decks: `decks:` in the config (`DeckDef`: id, name, `cards: CardDef[]`; deck and card ids share the id namespace, each deck also owns `<id>_pile`). The generated ink declares `LIST <deck>` with the cards and `VAR <deck>_pile` holding what is left; `draw(deck)` asks `roll_dice(LIST_COUNT(pile), "<deck>")` for a position and takes the k-th lowest card out (`nth_card`), `shuffle(deck)` is `LIST_ALL`, `deck_left(deck)` is `LIST_COUNT`. The engine recognises the deck by the label, reads the pile from the state to size the die and name the card (`DiceRecord.deck`), and `hud().decks` lists each pile; the fallback draws the lowest card. A hand is any list the story keeps.
- Tabletop slice 3, hands and card play: `hands:` in the config (`HandDef`: id, name) names the list variables shown as rows of cards; the generated ink declares each as `VAR <id> = ()` plus `VAR played = ()` (`InkNames.played`). `parsePlayTag` reads `#play:<hand>` on a choice; `engine.playOf(choice)` gives the hand and the cards in it (`ChoicePlay`, `known` false for a hand the config lacks), `engine.playPayload(hand, card)` the `Payload` that takes the choice (`{ var: played, item: card }`), `hud().hands` every hand's cards (`HandView`/`CardView`, deck order), `cardName(id)` a localized name. `PlaySession.choose(index, payload?)` writes the payload's variable (a list item via `InkList.FromString`, or text) just before `ChooseChoiceIndex`, restores the state if either throws, and records the pick as `{ index, payload }` (`Pick`; plain numbers stay for older saves) so back, save/load and the language replay carry it; `Chosen.payload` lets `main.ts` name the card on the turn line and in the journal (`withCard`). `canChoose` is false for a `#play` choice whose hand is empty or unknown. The explorer expands a `#play` choice into one move per card (`movesFrom`, `Move.payload`/`label`, `checks.unknownHands`), the random player picks a card at random, and both name cards in the story's language. The panel (`renderHands`, `picked` forgotten when the spot changes, rows keep their scroll position on re-render) and the web player (`#hands`, `picked`, `choose(index, text, payload)`, picks with payloads) render the rows; `#input` (slice 5) will reuse the payload. `api.choose(choice, card?)`, `panel().game.plays`.
- Tabletop slice 4, map: `map:` in the config (`MapDef`: image, width/height (default 100 = percentages), `places: PlaceDef[]` with x/y, links, hidden, counter + counterName, `tokens: TokenDef[]` with color and a starting place; validated as `mapPlaces`/`mapLink`/`mapPlace`, ids in the shared namespace, each token also owns `<id>_at`). The generated ink declares `LIST places`, `VAR here = (first shown place)`, `VAR revealed = (shown places)` and `VAR <token>_at` (`InkNames.places/here/revealed/atSuffix`); the story assigns them. `parseGoTag` reads `#go:<place>`; `engine.goOf(choice)`, `engine.map(choices)` → `MapView` (places with revealed/here/counter/go = index of the choice going there, tokens with `at`). `PlayView.renderMap` (image via `vault.getResourcePath`, resolved by `mapFile` in main.ts next to the story then as a vault path; links as an SVG overlay; places absolutely positioned by percentage; a `#go` place is a button that chooses) and the web player's `renderMap` (`cfg.mapImage` = data URI made by `mapDataUri` in main.ts with `arrayBufferToBase64`). `api.panel().game.map`.
- Tabletop slice 5, cards from notes and maps from a canvas: `CardDef.attrs` (numbers, `numberFields` flattens nested objects with `_`) and `CardDef.image`; `readCard` normalizes a card entry (inline or a note's frontmatter), `attributes` in the config names attrs. `generateInk` emits `card_<key>(which)` per attr key (`InkNames.cardPrefix/cardParam`). `src/game/cards.ts`: `cardFromNote`, `resolveDecks(config, notes, dir)` fills `decks[].from` folders (sorted by name, validated again, only the new problems reported; a missing folder keeps `from` so `deckCards` stays quiet). `src/game/canvas.ts`: `mapFromCanvas` (image node = frame, text nodes = places with `?` hidden, edges = links; no image → bounding box + 40), `resolveMap` merges the note's `places` by id (x/y are NaN in the note until merged; the note's link/token checks are deferred while `map.from` is set). `src/game/resolve.ts`: `ConfigSource { read, notes }` and `resolveConfig` running tables, decks and map; `main.ts` provides the vault source (folder children, frontmatter from the metadata cache, body after `frontmatterPosition`) and `check-ink` a disk source (`yaml`). Card art: `main.ts` `cardArt` (resource URLs, set with the engine) → `GameView.cardImages`; the export embeds `cardImages` as data URIs (`vaultFile`/`dataUri` helpers also serve the map image). Panel and web card faces: `.inkwright-card-illustrated`/`.illustrated`, `.inkwright-card-attr`/`.attr`.
- Tabletop slice 6a, growing dungeon: `dungeon:` in the config (`DungeonDef`: `width`, `height`, `shapes: ShapeDef[]`, `from` a note of shapes). `src/game/dungeon.ts` is pure: a shape is rows of `#`/`.` with `doors` (`top:3` = the top edge of the first floor square in column 3; `left:2`/`right:2` by row), an optional `entry`, `kind` (default: corridor when no 2x2 floor block); `orientations(shape)` gives the four quarter-turns (doors turned and kept in reading order, door indices stay stable); the layout is text, `shape:x:y:rot:usedDoorIndices:mark` per room joined by `;` (`parseLayout`/`formatLayout`); `boardOf(def, rooms)` lays the rooms on the sheet in order (a room keeps the squares on the sheet that no earlier room holds, so a cut room needs no extra storage) and judges doors (free = the square outside is on the sheet and empty, used, blocked); `startLayout` puts the entrance at the middle of the lower edge; `placeRoom(def, layout, shape, fromRoom, k)` hangs a shape on the k-th free door (0 = whole dungeon), trying the rotations and the doors facing the parent door, the first whole fit wins, else the most squares (truncated), else the door is only used up; `markRoom`, `viewBox`, `wallsOf`, `shapesFromMarkdown` (`### id` heading + first fenced block; a row of `###` squares has no space after it so it is no heading). `resolveDungeon` (resolve.ts) reads `from`. The generated ink (`InkNames.dungeon*`, `beginDungeon/addRoom/markRoom`) declares `VAR dungeon`/`VAR room`, the pure EXTERNALs (bound lookahead-safe in `GameEngine.bindDungeon`, with no-engine fallbacks returning an empty dungeon) and the three wrappers acting on the VAR; `GameEngine.dungeon()` → `GridView` (rooms with squares/doors/mark/here, `walls`, `box`, `free`) for `PlayView.renderDungeon` (SVG, `.inkwright-dungeon-*`) and the web page's `renderDungeon`; `panel().game.dungeon`. Secret doors and paths: `Room.extra` (doors found later, written `+r.c.side` in the used field, drawn as used doors with negative indices); `placeSecret(def, layout, shape, room)` tries every wall edge of the room (not an existing door) with empty sheet behind it, sharing `hang()` with `placeRoom`; `linksOf(board)` joins rooms through used doors, `stepsBetween` (BFS, -1 when unreachable), `wayBetween` (the rooms walked into, in order) and `nearestFreeRoom`; room notes `noteGet`/`noteSet` on a `room.field=value;…` string (numbers read back as numbers), ink `notesVar` with the `roomNote`/`setRoomNote` wrappers; ink `secretRoom` wrapper and pure EXTERNALs `dungeonSecret/dungeonSteps/dungeonNearest`. Options `stretch` (max squares; `stretchedShape` duplicates the first equal row pair, else column pair, moving the door specs; `hang()` lengthens a whole-fitting corridor whose other doors all face a wall until one opens, kept as `shape*k` in the layout, `Room.stretch`) and `passages` (in `boardOf`, a non-corridor room's door against an earlier room's square is "used", so `linksOf` joins them).
- Tabletop slice 6b, party: `party:` in the config (`PartyDef`: `stats: PartyStatDef[]` with `max` a number or another stat id and `hidden`, `members: PartyMemberDef[]` with starting `stats` and `items`, `down` a stat id, `present` a stat id: members with it at 0 or less are left out of `hud().party`). The generated ink declares `<stat>_<member>`, `<partyTitle>_<member>` (string) and, with items, `<partyGear>_<member>` (an items list) per member (`InkNames.partyTitle/partyGear`, reserved only when there is a party); the story owns every number (no clamping). `GameEngine.hud().party` reads them (`PartyMemberView`: name, title, visible stats with `max` resolved per member, gear, down) for `PlayView.renderParty` (`.inkwright-party-*`, a card grid at the top of the HUD) and the web page's `renderHud` (one line per member, `.down` faded).
- Player input (PRD 4.4): `#input:<var>` on a choice, any story (no game needed). `src/play/input.ts` (`inputOf`, `inputPayload` trims and refuses empty text, `inputPlaceholder` = `[var]`); the payload is the session's `{ var, text }` kind, so back/save/load/language replay carry it like a card. A `#play` choice ignores `#input`. Panel: `PlayView` puts an `.inkwright-input` field above the button (button disabled until a line is typed, Enter submits, `typed` kept per spot like `picked`); controller `choose(index, value)` takes the card id or the text. Web page: its own `inputOf`, `typed`, `#choices input`. Explorer/random player type the placeholder (path `text ▸ [var]`); `playScript` takes `{ choice, text }` entries (else the placeholder) and records `input` on the transcript's choice; `api.choose` refuses an `#input` choice without text (`inputNeeded`). `withCard` in main.ts names the typed text on the turn line and in the journal.
- Tabletop slice 5½, chaos bag: `rules.kind: "bag"` (`BagRules`: `tokens: BagToken[]` with `value` and/or `auto: fail|success`, `count`, `id` (default the value as text or the auto kind), `name`; `partialBelow`). `resolve` draws one token from `bagPool` (tokens repeated by count) with replacement, `gradeBag` (auto fail → 0, auto success → 4, bonus + value ≥ difficulty → 3, within `partialBelow` → 2, else 1), `CheckResult.token` (`DrawnToken`), `total` = bonus + value, `rolls` empty; `chance` enumerates the pool, `averageRoll` is the mean token value (rounded) for the ink fallback, which compares `skill + avg >= difficulty` like a sum system. The engine copies the token's localized name into the record; `tokenText` (dice.ts) words a token (name, else auto wording, else signed value) for the panel (`.inkwright-chip`, a `?` while tumbling), the web page (`.die.token`) and the journal; the dice logs show it in place of faces. `readConfig` checks the shape (`rules.tokens`, `rules.partialBelow`), `validateConfig` reports `tokens` for an empty bag.

## Layout
- `src/compile/` pure logic: `paths` (INCLUDE scan/resolve, relative to the main story's folder), `include` (async preload → sync `CachedFileHandler`), `diagnostics` (parse `ERROR: 'file' line N: msg`, translate), `zh.ts` (zh table; each regex matches a real inkjs message), `compile.ts`.
- `src/play/session.ts` — `PlaySession`: time-sliced `ContinueAsync` loop guard, restart rebuilds Story from JSON, per-step translated errors, EXTERNAL fallbacks on.
- `src/compile/graph.ts` — divert graph from the parsed tree (duck-typed by `typeName`; minified class names). `src/graph/layout.ts` — layered layout. `src/views/GraphView.ts` — SVG view, pan/pinch zoom, node popover (open source / play from here).
- `src/export/web.ts` — standalone web page (inkjs runtime via `virtual:ink-runtime`, provided by plugins in `esbuild.config.mjs` and `vitest.config.ts`; player script is a plain-JS string, tested with happy-dom in `tests/web.test.ts`).
- `src/play/script.ts` — `playScript` (scripted play for the API; `pick` matches choices by index/text).
- `src/play/inspect.ts` — variable panel data: names from `variablesState._globalVariables` (state JSON omits defaults), values via `variablesState[name]`, visit counts from state JSON (compile uses countAllVisits; compiler-generated path segments hidden).
- `src/root.ts` — main-story lock rules, `LatestOnly`. `src/i18n.ts` — `T()` zh/en tables, language from `moment.locale()`.
- `src/views/` + `src/main.ts` — Obsidian wiring incl. settings tab (language: auto/zh/en). No unit tests; verify with the Obsidian CLI.

## Rules
- No Node/Electron APIs in `src/` (mobile). File IO only via Vault API.
- Any user-visible text goes through `T()` with both zh and en; tests enforce every en string differs from zh.
- New zh error entries: get the exact inkjs text by compiling a broken story first, then add a test with that text.
- Pure logic: write the failing test first. UI wiring: build, reload, then check `dev:errors` + a screenshot yourself before asking the user.
- `npm run lint` — the Obsidian community directory's checks: eslint-plugin-obsidianmd over `src/`, `package.json` (dependency replacements) and `manifest.json`, with `--max-warnings 0`, plus stylelint on `styles.css` (no `!important`). Must pass clean.
- `npm run check-release` — manifest/package/versions.json versions agree (and match the tag in CI); `npm run build` is reproducible (the directory rebuilds and compares main.js).
- CI (`.github/workflows/ci.yml`): test + lint + check-release on every push/PR; `main` is protected, so changes go through a PR and the `check` job must pass before merging. `claude-review.yml`: independent Claude review, only on the owner's own non-fork PRs (secret is the owner's token).
- Release cadence: batch merged PRs and release about once a week, not after every PR.
- Release: bump `manifest.json`, `package.json`, `versions.json` and add the version's notes to `CHANGELOG.md` (one PR); tag equals version without `v`; pushing the tag runs `release.yml`, which builds and creates a draft GitHub release with main.js, manifest.json, styles.css; publish the draft with the changelog section as its notes (`gh release edit <v> --notes-file … --draft=false`).

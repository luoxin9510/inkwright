# ink-cn 设计文档

日期:2026-10-29 · 状态:待用户批准

## 1. 意图与原因

做一个 Obsidian 插件 `ink-cn`,让作者在自己的 vault 里写 ink 剧本(inkle 的分支叙事语言)、直接试玩、查看 knot 跳转图谱,最终用它开发自己的文字冒险游戏。

为什么做:ink 擅长叙事逻辑但没有好的创作环境(Inky 功能有限、看不清大剧本的结构);Obsidian 擅长知识管理和链接可视化,但没有分支逻辑。两者互补。用户是中文作者,所以中文化是一等需求,不是附加项。

使用者:作者本人,桌面和手机上的 Obsidian。**暂时只自用,不考虑发布。**

## 2. 目标

1. 在 Obsidian 里打开、编辑 `.ink` 文件(语法高亮,中文标识符和中文标点正常)。
2. 在 Obsidian 里试玩当前剧本:改动后自动重新编译,点击选项推进,可重新开始。
3. 编译报错与警告以中文显示,并尽量定位到剧本中的行。inkjs 的报错是纯英文字符串,行号嵌在文本里(形如 `line N`),没有结构化字段,因此用正则提取行号;提取不到时只显示消息、不定位。
4. 插件界面全部为中文。
5. 第二期:把 knot/stitch 之间的跳转关系画成可交互图谱,点击节点跳转到剧本对应位置。
6. 桌面端和手机端 Obsidian 都可用。

## 3. 非目标

- 发布到 Obsidian 社区插件市场,或面向没有 Obsidian 的玩家的独立网页播放器。
- 修改 ink 语言本身(语法、关键字)。关键字保持英文。
- 在手机上开发插件代码;手机上只写剧本、玩、看图谱。
- 插件自带同步功能。
- 世界观笔记联动、存档与存档管理(留作以后)。

用户明确说明暂时没有"反目标"(一旦做了就算失败的东西)。

## 4. 约束

- **不能依赖 Node/Electron 专有 API**(直接读写文件系统、子进程等),因为要在手机 Obsidian 上运行。文件读写走 Obsidian 的 Vault API。插件清单标记为非仅桌面端(`isDesktopOnly: false`)。
- **界面要适配触屏**:选项按钮足够大;图谱不依赖鼠标悬停,支持点击、拖动、缩放。
- 编译与运行必须在 Obsidian 的 JS 环境内完成,不依赖外部进程或网络。
- 插件 id 不得包含 `obsidian` 字样(Obsidian 对插件 id 的要求);本项目 id 为 `ink-cn`。
- 手机上没有热重载;插件调试主要在桌面端。

## 5. 方案对比

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A(已选)** 新仓库,`inkjs` 作为 npm 依赖 | 插件只管自己的部分;中文化放在插件层(中文界面 + 编译报错对照表) | 维护负担最小,`inkjs` 升级直接跟进;改不了语言本身,报错对照表需随上游报错文本变化手动跟进 |
| B fork `inkjs` | 直接修改编译器源码,可从源头中文化报错、将来支持中文关键字别名 | 控制力强,但要长期维护编译器分支、手动合并上游 |
| C 基于 C# 版 `ink`(已 fork 为 `luoxin9510/ink`) | — | **排除**:C# 无法在 Obsidian(尤其手机)中运行 |

选 A 的理由:当前目标是个人使用并尽快跑通,对照表足以覆盖中文化需求。插件通过依赖引用 `inkjs`,将来需要时把依赖指向 fork 即可切换到 B,无需重写。

## 6. 已确定的技术决定

- 语言与形态:TypeScript 编写的 Obsidian 插件,独立仓库 `ink-cn`(本地 `~/Developer/ink-cn`,GitHub `luoxin9510/ink-cn`)。
- 剧本引擎:`inkjs`(含编译器的完整包,通过其 `inkjs/full` 入口);编译在插件内完成。报错通过编译器选项里的错误处理回调收集(类型分为 Author/Warning/Error,三类都会走回调);另外有错误时 `Compile()` 本身还会抛出 "Compilation failed.",必须用 try/catch 包住。
- **第一期支持 `INCLUDE` 多文件剧本**(用户已确认)。`inkjs` 通过 `IFileHandler` 接口**同步**读取被引用文件,而 Vault 读取是异步的,做法是:
  1. **预加载**:编译前从主剧本开始,逐行用正则匹配 `INCLUDE <文件名>`,用 Vault API 异步读取被引用文件,递归处理其中的 `INCLUDE`,结果放入内存缓存。预加载用"已访问集合"防止循环引用导致死循环;正则多匹配到的(例如注释里的 `INCLUDE`)无害,真正是否引用由编译器决定。
  2. **基于缓存的文件处理器**:自行实现 `IFileHandler`,同步地从缓存取内容(思路同 `inkjs` 自带的 `JsonFileHandler`,但它不支持相对路径,所以不能直接用)。
  3. **路径规则**:与 ink 官方(inklecate / Inky)一致,相对于**主剧本所在文件夹**解析,保证 Inky 写的多文件剧本放进 vault 可以直接用。
  4. **错误**:循环引用由 `inkjs` 编译器自己检测("Recursive INCLUDE detected");找不到文件时编译器报 "Failed to load",二者都进中文对照表。报错带文件名,可定位到出错的那个文件和行。
  5. **重新编译**:主剧本或其引用的任何文件被修改,都触发重新编译。
- **主剧本锁定**(用户已确认):试玩面板默认编译并运行当前打开的 `.ink` 文件;用户可以把某个文件"锁定"为主剧本,锁定后切换到任何子文件编辑,面板仍编译并运行主剧本。可随时解除锁定。
- 文件:`.ink` 文件存放在 vault 中,由插件注册扩展名并提供编辑视图。
- 试玩与存档:第一期只做"重新开始",**不做存档**(原先写法与非目标矛盾,已修正,我的决定)。存档放在"以后",届时以 vault 内普通文件保存;同步完全交给用户现有的 vault 同步方式。
- 开发环境:电脑上用终端(Ghostty)+ 编辑器开发,构建产物输出到 vault 的 `.obsidian/plugins/ink-cn/`,开发时配合 Hot Reload 插件。

## 7. 分期

- **第一期**:`.ink` 编辑视图 + 语法高亮 + `INCLUDE` 多文件支持 + 主剧本锁定 + 试玩面板(含重新开始)+ 自动重新编译 + 中文报错 + 中文界面。
- **第二期**:knot/stitch 跳转关系图谱,点击节点定位到剧本。
- **以后**:存档、世界观笔记联动(笔记属性生成 ink 的 `LIST`/`VAR`)、必要时切换到方案 B。

## 8. 交给实现者决定的事项

- 编辑视图的具体实现和高亮规则。我的倾向:基于 CodeMirror 6 扩展,配合 `TextFileView` 注册 `.ink` 视图;理由是 Obsidian 的编辑器本身就是 CM6,手机端同样可用(待在 §9 中验证)。
- 试玩面板放在侧边栏、分屏还是弹层,以及触屏下的具体交互。
- 编译报错对照表的格式(按报错模式匹配 / 按关键词)和覆盖范围;未命中对照表的报错保留英文原文并附中文提示。
- 图谱的数据提取方式与布局算法。注意:编译后的 JSON 会丢失源码行号,若要"点击节点跳到剧本对应位置",需要解析源码或使用调试元数据,这个依赖要在第二期开始前确定。
- 项目脚手架、构建与测试工具链的选择。

## 9. 未验证的假设(实现前需先确认)

- `inkjs` 的编译器在 Obsidian 手机端(WebView)能正常运行且性能可接受。
- Obsidian 的内置编辑器扩展机制在手机端同样可用。
- `inkjs` 报错文本的稳定程度,决定对照表的维护成本。
- `inkjs` 完整包(含编译器)的体积对手机端插件加载速度的影响。
- Obsidian 插件 id 不含 `obsidian` 的规则主要针对上架社区市场,自用侧载未必强制,这里遵守只是为将来省事。

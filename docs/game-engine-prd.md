# Inkwright 游戏模式 PRD

> 状态:草案 v0.1(2026-10-30)。决定项已和作者确认;标注"待定"的还没定。

## 1. 背景与目标

Inkwright 目前是 ink 的编写、试玩、调试环境。本项目在它上面加一个**游戏模式**:一套面向跑团式文字 RPG 的规则引擎和界面,让作者在 Obsidian 里(桌面和手机)写、玩、调试带技能检定和内心声音的叙事游戏,并导出成单个网页给玩家。

第一个作品:以控江宿舍为背景、四个可选主角的恐怖冒险游戏,恐怖可以转成喜剧。

目标:

1. 引擎、ink 剧本、剧本设计方法三者打通,跑出一个可玩的垂直切片。
2. 作者在手机上也能开发:设定、数值、文字在 Obsidian 笔记里写;逻辑密集的 ink 在电脑上写;两边都能试玩。
3. 玩家不需要 Obsidian:导出的网页在手机浏览器里玩。

## 2. 用户与平台

| 角色 | 平台 | 需要什么 |
|---|---|---|
| 作者(作者本人 + 协作的 agent) | Obsidian 桌面、iOS | 写剧本和设定,随时试玩,看到检定和数值在跑 |
| 玩家(朋友、公开试玩者) | 手机或电脑浏览器 | 打开网页就能玩,进度自动保存 |
| 测试(agent、CI) | 命令行 | 跑完所有分支,枚举检定成功和失败,确认每个结局可达 |

## 3. 核心体验

读一段文字 → 内心声音插话 → 看到带成功率的选项 → 选择并掷骰 → 不管成功失败,故事都往前走 → 数值变化反映在界面和后续文字里。

借鉴:

- 极乐迪斯科:技能是脑内会说话的人格;对话即玩法;被动检定不掷骰;白检定可重试、红检定一次性。
- 奥秘消退:6 个维度就能撑起长篇;声音有立场;开局 build 决定看得到什么内容。
- CoC:理智类资源的滚雪球;孤注一掷(付代价重掷)。

## 4. 规则系统

### 4.1 技能(5 个,每个也是一个内心声音)

| 技能 | 管什么 | 立场 / 口吻 |
|---|---|---|
| 理智 | 推理、理解规则、面对恐怖时撑住 | "这说得通,撑住。"冷静的分析者;恐惧高时它开始结巴 |
| 耐力 | 硬扛、熬夜、忍痛、不病倒 | "再坚持一下。"倔,爱抱怨,但不退 |
| 魅力 | 说服、糊弄、安抚队友、套话 | "这事能谈。"油滑,自我感觉良好,也最懂人情 |
| 洞察力 | 发现细节、看穿人、预感 | "注意到了吗。"低声的观察者;恐怖氛围的主要出口 |
| 力量 | 撞门、搬人、动手 | "砸。"话少,感叹号 |

- 等级 1–6。四个主角各有预设(见 §5),外加少量自由点。
- 以后扩到更多技能只需增加笔记和变量,引擎不改。

### 4.2 资源

- **恐惧**(0–100,主角和队友都有)。看到不该看的、理智检定失败都会涨;恐惧每满 25 点,理智检定 −1;到 100 触发剧本定义的崩溃事件。
  - 用"恐惧"而不叫"理智值",是因为理智已经是技能名,也和队友的恐惧值统一。
- 体力、物品等资源:待剧本需要时再加,引擎按同一套"有上下限、越界触发事件"的方式处理。

### 4.3 检定

- **骰子**:2d6 + 技能 + 修正 ≥ 难度。双 6 必成,双 1 必败。骰法在引擎里是可替换的规则文件(以后可换 d20、d100)。
- **难度阶梯**:6 轻松 / 8 简单 / 10 普通 / 12 困难 / 14 艰难 / 16 传奇。
- **结果五档**:大失败(双 1)/ 失败 / 部分成功(差 1–2 点)/ 成功 / 大成功(双 6)。剧本至少写成功和失败两条,部分成功和大成功、大失败可选。
- **主动检定**:挂在选项上,选项显示技能和成功率,选了才掷。
- **被动检定**:不掷骰,技能 ≥ 门槛就出现一段声音的插话或一个额外选项。
- **白 / 红**:白检定失败后,状态变了(升级、新修正)可以再试;红检定一次性。默认白。
- **孤注一掷**:失败后可以扣恐惧换一次重掷,只能一次。
- **修正**:来自状态效果、物品、在场队友的专长。界面把每项修正列出来。

### 4.4 失败也推进剧情

检定失败不能是"什么都没发生"。剧本规范:每个失败分支都要改变至少一样东西(恐惧、线索、队友关系、处境),并给出新的选项。这是写作规范,引擎用测试工具辅助检查(§8)。

## 5. 多主角与队友

- 四个可选主角:昕(作者本人)和三位同学(化名,待定)。技能表共用,数值不同:

| | 理智 | 耐力 | 魅力 | 洞察力 | 力量 |
|---|---|---|---|---|---|
| 昕 | 3 | 3 | 6 | 3 | 2 |
| 同学 A | 4 | 3 | 2 | 3 | 5 |
| 同学 B | 2 | 5 | 2 | 2 | 6 |
| 同学 C | 6 | 2 | 2 | 5 | 2 |

- 主线共用;差异来自数值、少量主角专属选项、每人一两个高光时刻。
- 选谁当主角,其余三人自动成为队友。队友有恐惧、信任两个值和一两个专长(在场时给某类检定 +1),不用完整技能表。队友的内心状态通过主角的"魅力"和"洞察力"声音讲出来。
- 所有非作者本人的角色用化名,包括 NPC。

## 6. 内容格式:Obsidian 笔记 → ink

一个游戏是 vault 里的一个文件夹:

```
游戏/控江/
  游戏.md            # 配置:名字、骰法、技能列表、资源、主角列表
  角色/昕.md …       # 主角:技能预设、简介、立绘;队友:专长、初始恐惧/信任
  技能/理智.md …     # 名字、立场、口吻、颜色(引擎渲染声音时用)
  main.ink           # 剧本入口
  _引擎.ink          # 由引擎从笔记生成:VAR 声明 + 检定函数的 ink 兜底
  第一夜.ink …       # 章节
```

- 笔记用 frontmatter 存数值,手机上用属性面板就能改。
- `_引擎.ink` 由引擎生成,作者不手改;没有引擎时(Inky、纯 Inkwright)剧本靠它的兜底函数照样能跑。

### 6.1 剧本里的写法(tag 协议)

| 写法 | 含义 |
|---|---|
| `* [撬开门 #check:力量:12]` | 主动检定(白)。标签写在方括号内,挂在选项上,玩家看不到标签 |
| `* [最后一搏 #check:力量:12:红]` | 红检定,一次性 |
| `{洞察力 >= 10: 门缝里的黑不是没开灯的黑。 #voice:洞察力}` | 被动检定 + 声音插话。条件在 ink 里,引擎按标签渲染成该声音 |
| `{检定("力量", 12) >= 3: 锁开了。 - else: 撬棍断了。}` | 剧本里读结果档位(0 大失败 … 4 大成功);技能名用字符串传,引擎按名字读等级并记录掷骰;`检定` 由引擎接管,ink 里有兜底 |
| `~ 恐惧 += 5` | 直接改资源,引擎观察到后更新界面 |
| `{当前主角 == 昕: …}` | 主角专属内容 |
| `#fear:同学A:+10`(待定) | 队友状态副作用的标签写法,待定是否需要 |

状态唯一在 ink 里(VAR / LIST);引擎只读、只渲染、只掷骰,写入只有三样:开局推送主角预设、每局一个骰子种子(`骰子种子`)和掷骰计数(`掷骰次数`)。后两者随状态存档、回退、换语言重放一起还原,第 n 次检定的骰面由(种子, n)算出,所以重放永远掷出同样的骰子,不会因为切换语言或回退而改变结局。

## 7. 引擎功能

### MVP(垂直切片需要的)

1. 规则核心(纯逻辑,可测试):骰法、五档判定、成功率计算、修正汇总。
2. 游戏模式的试玩面板:选项上显示技能和成功率;掷骰动画和骰子日志;声音插话的样式;恐惧和队友状态的 HUD。
3. 开局选主角,把预设推进 ink。
4. 从笔记生成 `_引擎.ink`。
5. 导出的网页带上引擎(同样的规则核心和界面)。
6. 测试:`explore` 能枚举每个检定的成功和失败,而不是随机掷;报告哪些失败分支"什么都没改变"。

### 之后

技能成长(剧情给点)、思想柜、战斗回合、地图(可复用 atlas-vtt)、AI 队友对话、多周目。

### 非目标

不做通用 RPG 框架;不做战斗系统;不做图形场景;不替代 Inky。

## 8. 验收:垂直切片

- 一个晚上、一栋宿舍楼、3–4 个场景、2–3 个结局。
- 四个主角都能选,至少每人一个专属时刻。
- 每种检定方式各出现一次:主动、被动、红、孤注一掷。
- 每个失败分支都改变了状态并给出新选项。
- `explore` 跑通全部分支和两种语言(如果做双语),没有运行时错误。
- 在 iPhone 的 Obsidian 里能试玩;导出的网页在手机浏览器里能玩。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 手机上写逻辑密集的 ink 效率低 | 插入检定、插入声音的命令;逻辑在电脑写,手机写设定和文字 |
| 五个声音每个场景都要台词,写作量大 | 被动插话按门槛筛,不是每个场景每个声音都说;先做短切片 |
| 真实同学的隐私 | 除作者本人外全部化名;公开前过一遍 NPC 描述 |
| 随机检定让全分支测试无法穷举 | 掷骰在引擎侧,测试时强制走成功和失败 |
| 2022 年封控题材的分寸 | 切片阶段只做"宿舍的一个晚上",封控是否作为前提待定 |

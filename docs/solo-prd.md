# 单人游戏 PRD(单人 TRPG、单人桌游、文字冒险)

> 状态:草案 v0.3(2026-11-04)。v0.1、v0.2 各经过一轮对抗式审稿;v0.3 定下了存档位置(vault 里的文件夹,同步方式可配置,默认 iCloud),按第二轮意见重写了核对、种子、重放、动作日志的字段和第一刀的范围。标"建议"的待定项等作者确认。
> 接在 `game-engine-prd.md`(检定引擎)和 `tabletop-prd.md`(骰、表、牌、地图、小队)后面。

## 1. 背景与目标

- 现状:Inkwright 是一个好用的**作者工具**:写剧本、随写随玩、`check-ink` 走遍分支、`--random` 调数值;游戏模式和桌游原语(检定、资源、物品、骰与表、牌堆手牌、地图、生长的地城、小队、混沌袋、玩家写字)都有了。
- 缺口:单人游戏里作者和玩家常常是同一个人,一局要玩好几个晚上,还会边玩边改。**玩家这一侧**还很薄,现有的存档也撑不起长局:
  - 每次重新编译(改一个字)都新建会话、从起点重来(`main.ts` 的 `recompile`);重启 Obsidian 也一样。
  - 手动存档能读档,但读档后不能回退、骰子卡片不显示、"写成笔记"里没有选项行(`PlaySession.load` 清空 `history`、`chosen`,`turnOf` 全为 null)。
  - 存档里的 `picks` 只有选项序号和 payload,没有选项文字;起点存的是整份 ink 状态。剧本一改,`LoadJson` 找不到原位置时**只发 warning、就近定位**(inkjs `CallStack.js`),读进来的局可能悄悄走错地方。
  - 所有存档和设置在一个 `data.json` 里,每次整份写入,也没有处理 `onExternalSettingsChange`;两台设备交替玩会互相覆盖。
  - 所有随机都由剧本触发;玩家想主动问"门后有人吗?"问不了。
  - 日志是一次性的命令;面板引擎只在内存里留最近 20 条掷骰记录。
- 目标:让 Inkwright 成为**在 Obsidian 里玩单人游戏**的地方:单人 TRPG(神谕驱动的跑团)、单人桌游(调查卡牌式、地城探索)、文字冒险。玩一局 = 写成一篇笔记;下次打开接着玩,换台设备也接着玩。
- 一句话:**存得住、问得了、看得见、留得下**。

原则:剧本的状态留在 ink 里;**玩家侧的动作留在动作日志里**;引擎只补 ink 做不了或做得难看的;系统差异用 `game.md` 加 ink 写,不做通用规则 DSL;ids 英文,玩家看到的名字双语。

**对前两份 PRD 的修正**:
- `tabletop-prd.md` "神谕不单做,一张表就是神谕":剧本里的神谕仍然是表;玩家**主动提问**剧本触发不了,所以加一个玩家侧的骰盘(§4.3)。
- `tabletop-prd.md` "进度条就是资源":保留;时钟和进度条只是资源的显示方式(§4.4)。
- `game-engine-prd.md` "引擎写入只有三样(预设、骰子种子、计数)":玩家的手动调整(§4.4)是第四样,但它是**玩家动作**,记进动作日志,由会话在两次选择之间写入,不是引擎自己写。第三刀时同步改那份 PRD。

## 2. 用户与场景

| 用户 | 场景 | 要什么 |
|---|---|---|
| 单人跑团玩家 | 一个人用规则加神谕玩一场战役,几周 | 随时问神谕、掷骰、自己改数值;进度条和时钟;日志自动成文 |
| 单人桌游玩家 | 移植或自制一个调查卡牌式、地城式的单人桌游 | 敌人、回合阶段、出牌;几十回合不丢进度 |
| 文字冒险作者兼玩家 | 写一个探索型文字冒险,边写边玩 | 改剧本不丢进度;背包里挑东西用;设定笔记一点就看 |
| 想入门的人 | 不懂 ink,想先玩起来 | 一条命令生成一个能玩的模板 |

平台:Obsidian 桌面和手机,同一个 vault;同步方式可能是 iCloud(默认)、Obsidian Sync、git / Syncthing,或者只在一台设备上;导出的网页照旧能玩。

## 3. 核心体验

打开一个游戏 → 面板接着上次的地方,先给出上次最后几段和一条"上次玩到这里" → 读、选、掷;想问什么就在骰盘问神谕,答案以卡片出现在正文 → 自己给进度条勾一格、给 HP 减一点 → 日志笔记一直在长,玩家在里面随手批注 → 关掉 Obsidian;第二天在手机上打开,接着玩。

## 4. 功能

### 4.0 动作日志和存档(所有续玩功能的地基)

一局不存成"一份 ink 状态",而是**一串动作**:从起点开始玩家做过的每件事。续玩、回退、换语言、改剧本后重放、实时日志、骰盘都建立在它上面。`schema: 1` 随第一刀发出,以后改格式要迁移,所以下面的字段第一刀就全部定下(用不到的先留空)。

```ts
interface Run {
  schema: 1;
  id: string;                   // 一局的 id;一个剧本可以有好几局
  story: string;                // 主剧本路径(改名时跟着改,见存储)
  name: string;
  draft: boolean;               // 作者模式的草稿局,不进局列表(见 4.1 的"重新开始")
  createdAt: string;
  startPoint: string | null;
  character: string | null;     // 游戏模式选的角色
  seeds: { story: number; dice: number; oracle: number };
  actions: Action[];
  pending?: Action[];           // 重放停下时还没走的动作,不丢(4.1)
  journal?: { path: string; writtenSeq: number };
}

type Action = { seq: number; lang: string | null } & (   // seq 单调递增,回退后也不复用
  | { kind: "choose"; index: number; text: string; payload?: Payload; fp: string }
  | { kind: "oracle"; question?: string; odds: string; result: OracleResult }   // 骰盘(4.3)
  | { kind: "roll"; formula: string; table?: string; result: RollResult }       // 骰盘的自由骰、灵感表
  | { kind: "adjust"; var: string; delta: number }                               // 手动加减(4.4)
  | { kind: "set"; var: string; value: number | string }                         // 手动设值(4.4)
  | { kind: "record"; record: string; op: "add" | "remove"; entry: string }      // 手动改记录(4.5)
);
```

- `choose.text` 是选项当时的原文,`lang` 是当时的语言;局中换语言,之后的动作带新的 `lang`,核对时按每个动作自己的语言比。
- `choose.fp`(结果指纹):这一步掷骰的序列(种类、标签、总值、档位、抽到的牌)加上下一屏选项的个数,hash 一下。**不用变量**:作者加一个 VAR、改一个初值(这些改动应该生效)不能让每一步都报差异。
- `Payload` 扩展成 `{ var, item } | { var, items } | { var, text }`(`items` 给一次出几张牌,4.8)。
- 骰盘的 `result` **存进动作**:重放和续玩直接用存下的结果,不重算,所以以后改了神谕阈值或表,过去的答案不会变。新的骰盘动作用 `seededDice(seeds.oracle, n)` 掷,`n` 是这一局里骰盘动作(oracle 和 roll 共用)的个数。
- **回退 = 撤销最近一个动作**,不管它是哪种。回退一个骰盘动作后再问,`n` 回到原来的值,得到同一个答案(防止用回退重掷)。
- `seq` 单调递增,回退后也不复用;实时日志按它补写(4.7)。

**种子的注入顺序**(新建 Story 时,`PlaySession` 加一个 `prepare(story)` 钩子):
1. `new Story(json)`;
2. `setup`:绑定 EXTERNAL、写角色预设(引擎);
3. 写种子:`state.storySeed = seeds.story`、`state.previousRandom = 0`(ink 的 RANDOM 用两者之和)、`dice_seed = seeds.dice`、`dice_rolls = 0`;
4. 设语言;
5. `ChoosePathString(startPoint)`(有起点时);
6. `advance`。

剧本里没有 `dice_seed` / `dice_rolls` 变量时(引擎文件过期或没有 INCLUDE),引擎用构造时给的 `seed` 和自己的计数掷骰;重放按同样的顺序调用,所以结果一样。

**存档位置:vault 里的一个文件夹**,默认 `Inkwright/存档/`(界面是英文时默认 `Inkwright/Saves/`;第一次使用时定下并写进设置,可以改)。
- 放在 vault 里,任何同步方式都会带上,玩家看得见、能备份。`.json` 文件默认不出现在 Obsidian 的文件列表里(除非打开"检测所有类型文件"),不会弄乱笔记。
- 结构:`<文件夹>/<剧本 id>/<局 id>/<设备 id>.json`。
  - 剧本 id:第一次为一个主剧本建局时生成,和剧本路径的对应表存在 `<文件夹>/index.json`;剧本改名或移动时(`vault.on("rename")`)只改对应表。
  - 设备 id:用 `app.saveLocalStorage` 存在本机(不同步),第一次启动时生成。
  - **每台设备只写自己的文件**,读的时候合并同一局的所有设备文件:一份的动作是另一份的前缀,就取长的;分叉了,就把分叉的那份另存成"冲突副本"一局,在局列表里提示,两份都在。
- 别的设备改了存档:文件在 vault 里,同步写入会触发 `vault.on("modify")`,面板据此重读(不是 `onExternalSettingsChange`,那只管 `data.json`)。面板打开、获得焦点、`visibilitychange` 时也重读一次。存档文件夹不当编译依赖,改存档不触发重新编译。
- **写入时机:只有玩家的动作会写存档**(选择、回退、骰盘、手动调整、重新开始)。重放、停下、重新编译都不写;每个玩家动作后立即写(文件小),不防抖,手机后台被杀最多丢正在做的那一个动作。
- **同步方式**(设置里选,默认 iCloud),只影响冲突处理和提示,存储结构都一样:
  - **iCloud**(默认):iCloud 冲突时会生成 `<名字> 2.json` 这样的副本,读的时候把它们也当成设备文件合并,然后清理;刚打开时文件可能还没下载完,先读到什么用什么,文件变化后再合并。
  - **Obsidian Sync**:设置页提示要打开"同步所有其他类型的文件"(`.json` 不是笔记)。
  - **git / Syncthing 等**:每台设备一个文件,不会产生合并冲突;不做特殊处理。
  - **只在本机**:不分设备文件(固定一个设备 id),不检查冲突。
- **迁移**:`data.json` 里的旧存档(`SaveSlot`)第一次启动时迁移成局:有 `start` 和 `picks` 的变成按序号重放的局(动作没有原文,标成"旧存档,只按序号核对");只有状态的保留成"只能读档"的旧存档,照旧能读。迁移可以重复执行;另一台设备还在用旧版插件、往 `data.json` 里写存档时,`onExternalSettingsChange` 触发后再迁移一次。
- 备份:一局可以导出成一个 `.json`、再导入(第一刀 c)。

### 4.1 续玩和改剧本后的重放

**续玩一律走重放,不读旧状态。**打开剧本 → 选这个剧本最近玩的那一局 → 用当前剧本按 4.0 的顺序新建起点 → 按 `actions` 重放。回退、骰子卡片、日志里的选项行都和没关过一样;改过的初始值和角色预设也会生效。面板引擎保留这一局的全部掷骰记录(`keepRolls: Infinity`)。

**重放是异步的、可以取消**:`replay(actions, { signal, budgetMs, onProgress })` 每约 16 ms 让出一次主线程,面板显示进度、期间不能点;又来了一次编译就取消重来。两种停法分开报:
- 某一步死循环(现有的单步 2 秒保护)= 报错,剩下的进 pending;
- 总预算用完(待定:桌面 5 秒、手机 10 秒)= 停在已到的位置,剩下的进 pending,提示"太长没重放完"。

**核对每一步**(第一刀 a 只有第 1 条,b 加上其余):
1. 同序号,且原文和存下的 `text` 完全相同(按这个动作的 `lang`)→ 走。
2. 换了序号,但新选项里**只有一个**原文完全相同 → 走它。
3. 去掉数字后**只有一个**相同 → 走它,标成"推测"。
4. 同一屏选项个数没变、其他选项原文全都一致,只有这一个不同 → 认作"改了措辞",走它,标成"推测"。
5. 都不成 → 停。

不用 inkjs 的 `pathStringOnChoice`:它是选项在 weave 里的序号路径(`k.0.c-1`),删掉前面一个选项,后面的就补上来;ink 里的 label 编译后也不在运行时 JSON 里。要给选项稳定的身份,之后可以在编译时从 parsed tree 建一张"路径 → knot.stitch 和 label"的表,只有加了 label 的选项有身份;教程推荐给关键选项加 label。

**结果指纹**:选项对上了,`fp` 却和原来不同(前面多了一次掷骰、改了骰法、ink 的 RANDOM 或洗牌随内容变了结果),面板提示"从第 N 步起结果和原来不同",只报第一个位置,不拦着玩;玩家可以选"停在第 N 步"。

**停下时不截断**:没走完的动作存进 `pending`,只有玩家在停下的地方做出新动作时才丢弃;存档文件不变(重放不写存档)。面板给出口:
- 第一刀 a:"停在这里"。
- 第一刀 b 起:"按序号接着走"(pending 只按序号走,走不通再停);"回到改之前"(见下)。

**冻结旧版**(第一刀 b):编译好的剧本 JSON 和解析后的配置按 hash 存在 `<文件夹>/<剧本 id>/builds/<hash>.json`(每个剧本留最近 3 份),一局记下它最后在哪个版本上玩。面板里的"一局"由一个 `RunHost` 管(会话、引擎、配置、剧本 JSON 一起),重新编译换的是新的 `RunHost`,旧的可以留着。于是:
- "回到改之前"= 用旧版本的 `RunHost` 接着玩,重启后也能;
- 玩家模式下剧本改了不打断,接着用旧版本,顶上一条"剧本已更新,点此应用"。

**起点或角色在新剧本里不存在**:停下、明确报错,这一局原样不动(现在会悄悄改成从头开始、换成第一个角色)。

**什么时候重放**:作者模式下,编译(停手 300 ms)照旧,重放另外调度:面板可见(`containerEl.isShown()`)、停手约 2 秒才重放;面板不可见不重放。

**重新开始、换角色、多局**:
- 作者模式:每个剧本有一个**草稿局**(`draft: true`,不进局列表),"重新开始"和换角色只是重置草稿局。
- 玩家模式:"重新开始"和换角色**新开一局**,旧的留在局列表里。
- 局列表:按最后游玩时间排,打开剧本默认进最近的那一局;可以改名、删除(删除要确认)。

**API**:`api.runs()` 列出这个剧本的局,`api.run()` 返回当前这一局的动作日志;`save(name)` 变成"复制成新的一局",`load(id)` 能读局也能读迁移来的旧存档;vault 的 `CLAUDE.md` 同步。

**网页导出**(第一刀 b):网页也用同一套动作日志和核对,不再因为重新导出就清空玩家进度(现在按剧本 JSON 的 hash 清档)。核对逻辑写成纯函数,单独打包进**所有**导出的网页(纯剧本的网页不带游戏引擎);网页存档里回退历史仍只留 50 步。

### 4.2 玩家模式和回顾(第一刀 c)

- 面板一个开关(也在设置里):隐藏变量面板、knot 起点这些作者控件,报错收成一个小标记;正文排版偏阅读。打开时**自动锁定**当前主剧本(不锁定的话,打开一个 INCLUDE 的章节就会换主剧本)。保留回退、存档、局列表。
- **回顾**:隔了一段时间(待定:超过一小时)再打开,正文停在上次最后几段,下面一条"上次玩到这里 · 11 月 3 日 22:10",接着是选项。
- 面板正文只渲染最近若干段,更早的折叠。

### 4.3 骰盘(玩家主动问)

面板一个常驻的骰盘,剧本有没有 `game.md` 都能用。每次使用是一个动作(4.0),结果存进动作;卡片出现在问它的那一屏的正文后面,进日志。

- **是否神谕**:玩家写一句问题(可选),选可能性:几乎肯定 / 很可能 / 一半一半 / 不太可能 / 几乎不可能,对应阈值 `t` = 90 / 75 / 50 / 25 / 10。掷 d100 得 `r`:
  - `r ≤ t` 为"是";其中 `r ≤ round(t / 5)` 为"是,而且";
  - `r > t` 为"不";其中 `r > 100 - round((100 - t) / 5)` 为"不,而且"。
  - 这是原创的默认规则;措辞走 `T()` 双语;`game.md` 的 `oracle:` 可以改阈值和措辞。
- **混沌值**(可选):`oracle.chaos` 指向一个资源,阈值加上 `(chaos - 中值) × 每格偏移`(具体在 `oracle:` 里写明,待定默认值)。
- **自由掷骰**:输入公式(`2d6+1`、`4d6kh3`、`5d6>=5`)或点常用骰。
- **灵感表**:`tables` 里标了 `oracle: true` 的表出现在骰盘上(比如"动作 × 主题"),点一下掷一次。
- **不改剧本变量**:问答是玩家的想象;要影响数值,玩家用手动调整(4.4);剧本要用随机就在剧本里 `roll` / `table`。
- 网页导出:先不带(建议);面板版稳定后再说。

### 4.4 时钟、进度条和手动调整

- 时钟和进度条是资源的显示方式,复用资源已有的 min/max、夹紧、越界检查和 HUD:
  ```yaml
  resources:
    - { id: doom, name: { zh: 末日, en: Doom }, min: 0, max: 6, initial: 0, display: clock }      # 六格时钟
    - { id: vow, name: { zh: 誓言, en: Vow }, min: 0, max: 40, initial: 0, display: track, manual: true }   # 十格进度条,每格 4 勾
  ```
  `clock` 的格数是 `max - min`;`track` 的格数是 `(max - min) / 4`(不整除时报配置问题)。默认 `bar`(现在的样子)。
- **手动调整**(玩家就是主持人):资源标了 `manual: true` 才能在 HUD 上改。点加减是 `adjust` 动作(记增量,作者改了前面的伤害,重放后仍然是"在那时的值上减 1");直接输入数值是 `set` 动作。照样夹紧。
  - 在两次选择之间写入;**这一屏的选项不会因此刷新**(ink 的选项在出现时就算好了),界面写明"从下一个选择起生效"。
  - 重放时变量不存在了(作者删了这个资源),跳过这个动作并提示,不停下。
  - 探索器和随机试玩不会做手动调整:靠手动推进度才能到的结局,`check-ink --all` 走不到。`check-ink` 对"选项条件读了 `manual` 资源"的地方给提示;教程写明这是限制。
- 动态的时钟和誓言(玩到一半才建的):之后用"槽位池"做,本 PRD 先不做。

### 4.5 记录(线索、NPC、悬念)

- 名字叫"记录"(`records:`),不叫 list,免得和 ink 的 `LIST` 混。
- 一个记录是一个字符串变量(存条目)加一个计数变量 `<id>_count`;生成的 ink 给出 `record_add("clues", "旧磨坊")`、`record_remove`、`record_count`、`record_pick("clues")`。
  - 增删由引擎的纯函数 EXTERNAL 做,存储格式定义转义(条目里可以有任何字);`record_pick` 走 `roll_dice` 加 `record:<id>` 标签,卡片显示"线索:抽到 旧磨坊"。
  - 没有引擎时(Inky 里预览):`count` 用计数变量,照常;`add` 只追加不转义;`pick` 返回空字符串。写明只是预览。
- 玩家可以用 `#input` 或手动改记录(`record` 动作)往里加。
- 面板状态区列出各记录;`ink: zh` 预设另有一套中文名字。

### 4.6 写一段(多行输入)

- 新标签 `#write:var`(不扩展 `#input`):多行文本框,写的一整段进变量。
- 面板和日志保留换行;写进日志前转义,放进引用块。
- 剧本打印这个变量时 ink 会怎么分段,第四刀先写测试验证;必要时剧本里用专门的函数打印。
- 配合牌堆当"提示卡":抽一张提示 → 写一段。日志型游戏的主循环。

### 4.7 实时日志

- `game.md` 的 `journal: { live: true }`(没有 `game.md` 的剧本在设置里开):这一局第一次玩家动作时建日志笔记,路径定下后存进 `Run.journal`,跨天续玩写同一篇。只在玩家模式,或玩家第一次做选择之后才建。
- **只追加,按 `seq` 补写**:每个动作一块(选项、它带出的正文、骰子和骰盘卡、写的段落),块上带 `seq`。`Run.journal.writtenSeq` 记写到了哪里;每次写、每次打开都把 `seq > writtenSeq` 的块补上,重复执行不会写重,手机后台被杀后下次打开补齐。回退只追加一行"↩ 回退到第 N 步"。
- 日志笔记正开在编辑器里时,用 Editor API 在文末插入(不和玩家的光标抢);没开时用 `vault.process`。
- 日志路径不能落在任何编译依赖(`from:` 的表、牌堆文件夹)里,配置检查时报问题。
- 现有的"把这局写成笔记"保留(一次性导出整局)。

### 4.8 单人桌游补件

- **敌人区**:敌人多半是从牌堆里抽出来的,所以敌人区是一个牌区(`kind: foes`),牌面显示牌的属性和伤害。伤害按牌 id 记在一个字符串变量里(和 `room_notes` 同一种做法),生成 `foe_damage(card)`、`set_foe_damage`、`remove_foe`(移出牌区并清掉伤害)。同名的多只敌人用 `copies: n` 生成 `ghoul_1..n` 几张牌。
- **回合和阶段**:`turn: { round: <变量>, phase: <变量>, phases: [{ id, name }] }`,阶段变量是字符串(不进 LIST,免得和牌、物品、地点撞名),HUD 一行"第 3 轮 · 敌人阶段"。
- **一次出几张牌**:`#play:hand:1-2`(张数下限和上限),选中的牌一起写进 `played`(payload 的 `items`,逐个转成 ink 列表项)。explore 只走"每张单出"和"全出"并标成抽样;`--random` 随机挑。
- **从背包里用东西**:`#use`(选项上),玩家从背包挑一件,写进 `played`(有物品时就生成 `played`)。

### 4.9 文字冒险补件

- **设定笔记联动**:正文里的 `[[笔记]]` 渲染成链接,桌面悬停预览、手机点击打开;导出网页时去掉括号显示纯文字。只推荐最简写法:`[[笔记#标题]]` 的 `#` 在 ink 里是标签,`[[笔记|别名]]` 的 `|` 在条件和序列里是分隔符,选项方括号里也不行;`.ink` 不被 Obsidian 索引,笔记改名后链接不会跟着改。
- **走过才显示的地图**(之后)。

### 4.10 模板和示例

- 命令"新建单人游戏":先只做一种模板——**日志型**(抽提示卡 → 写一段 → 骰盘问答 → 实时日志)。其他类型以后逐个加。
- 模板原创、双语,带 `check-ink` 通过的剧本;模板文字不打包进 `main.js`,放在单独的资源里按需读(待定)。
- 每一刀带一个教程小节和示例(第九章"单人游戏")。

### 4.11 角色卡和战役(推迟到最后)

前提(不满足就不做):
- 笔记来的角色由引擎在运行时写入预设,不进生成的 `_engine.ink`。
- 角色笔记**不当编译依赖**:改了它只影响下一局,不重放当前局。
- 只用命令写回(结局时只提示),重放中禁止写回;写回前列出变化让玩家确认,并在日志里留旧值。
- frontmatter 用扁平的键;`processFrontMatter` 会重写整段 YAML(注释和格式会丢),写明代价。
- 角色卡的形状另定(现在的 `CharacterDef` 没有资源和小队数值,技能有上限校验)。

## 6. 分刀

每刀一个 PR:测试先行、CHANGELOG、教程一节、vault `CLAUDE.md` 同步,在 Obsidian 里自己验过再交。每刀写明只做面板还是面板和网页都做(网页播放器是另一份纯 JS 实现,做两遍工作量翻倍)。

| 刀 | 内容 | 面板 / 网页 |
|---|---|---|
| 一 a | `schema: 1` 动作日志(字段一次定全)+ vault 文件夹存档(每设备一个文件、合并、同步方式设置、改名跟随)+ 旧存档迁移 + 种子注入 + 续玩走异步重放 + 重新编译时严格重放(只认同序号同原文,否则停下进 pending)+ 只有玩家动作才写存档 + 草稿局和局列表 + `keepRolls: Infinity` + API 兼容 | 面板 |
| 一 b | 核对的 2–5 条、结果指纹提示、"按序号接着走"、冻结旧版(builds、`RunHost`、"回到改之前")、网页用同一套核对不再清档 | 面板和网页 |
| 一 c | 玩家模式、回顾、只渲染最近若干段、局的导出导入 | 面板 |
| 二 | 骰盘(神谕、自由骰、灵感表);一次性日志带上骰盘记录 | 面板 |
| 三 | 资源的时钟 / 进度条显示 + 手动调整(`adjust`、`set`、`manual`) | 面板和网页(显示) |
| 四 | 只追加的实时日志 + `#write` | 面板(网页只支持 `#write`) |
| 五 | 记录 + 桌游补件(敌人区、阶段、几张牌、`#use`) | 面板和网页 |
| 六 | 日志型模板 + 设定笔记联动 + 第九章教程 | 面板 |
| 之后 | 角色卡和战役、checkpoint 加速、长局封存、选项身份表、动态时钟、走过才显示的地图、骰盘上网页、更多模板 | |

**测试夹具**(第一刀 a 起):`tests/fixtures/replay/` 放"改前剧本 / 改后剧本 / 动作日志 / 期望"一组组,每条核对规则一组:插入、删除、改措辞、调换顺序、重名选项、条件块里的选项、tunnel、thread、数字插值、双语。

## 7. 非目标

- 多人、联机、主持人模式。
- 解析器式文字冒险(输入"take lamp"):ink 是选项式的。
- 通用规则 DSL、自动战斗、自由拖放的桌面。
- 把非开放许可的规则书(如 Mythic GME、诡镇奇谈)的文字或表格放进仓库和模板;私下移植只在自己的 vault 里。开放许可的(Ironsworn 核心规则据称为 CC BY 4.0,Blades in the Dark SRD 为 CC BY,**待核实**)可以署名引用,但内置的默认神谕和模板仍然原创。模板名避开商标("调查卡牌",不叫"诡镇")。

## 8. 验收

**能写成自动测试的**(vitest,接着现有的 session、saves、journal、web 测试扩):
- 同一份动作日志在全新的 Story 上重放两次,结果完全相同(RANDOM、洗牌、检定、自由骰、抽牌);没有种子变量的剧本也一样。
- 核对夹具表:每条规则一组,包括"删掉第 10 步那个选项 → 停在第 10 步,pending 保留"。
- 指纹:前面插一次 `roll`,在第 N 步报差异;加一个 VAR、改一个初值不报。
- 停下不截断,重放和停下不写存档。
- 旧 `SaveSlot` 迁移(有 `start` 和没有 `start` 两种),重复迁移不重复。
- 设备文件合并:前缀取长;分叉生成冲突副本;iCloud 的 `x 2.json` 被并进来。
- 起点或角色被删:停下报错,存档不动。
- 回退跨过骰盘、`adjust`、`set` 动作;回退后再问得到同一个答案;改了神谕配置后旧答案不变。
- 局中换语言后续玩;带出牌和写字的局续玩;超过 20 次掷骰后骰子卡片都在。
- `adjust` 指向被删的资源:跳过并提示。
- 日志补写不重复(第四刀)。
- 网页重新导出后能续玩,纯剧本和游戏两种(第一刀 b)。

**用 Obsidian CLI 在桌面验**(`plugin:reload` 代替重启,vault 规则禁止退出整个应用):
- 第一刀 a:玩到第 20 步,`plugin:reload`,接着第 20 步,能回退,骰子卡片和选项行都在;改第 25 步之后的一句话,停在第 20 步原样;改第 10 步的选项文字,停在第 10 步并提示,存档文件没变;作者反复"重新开始"只有一个草稿局;主剧本改名后局还在;只改 `game.md` 的规则、剧本不动,重放正常;重放期间面板显示进度,来了新编辑会取消。
- 截图看重放进度、停下时的出口。

**必须真机**:
- 桌面和手机(同一个 iCloud vault)交替各玩 5 步:两边的局都在,冲突时两份都留;Obsidian Sync 一样(核实"同步所有其他类型的文件"的要求)。
- 手机上重放的时间:用 dorm-302 `--random --seed 7` 生成的一份 300 步动作日志作夹具,不超过预算。
- 手机后台被杀:最后一个动作之前的都在。

**第二刀**:骰盘的神谕、自由骰、灵感表都能用;回退、续玩、换语言、改剧本重放后骰盘记录一致;"写成笔记"里能看到问答。

**全部**:`check-ink --all` / `--random` 认得新标签和新配置(`#write` 填占位串、`#play:hand:1-2` 抽样、`#use`);导出网页能玩;手机能玩;所有界面文字中英两份。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 两台设备交替玩互相覆盖 | 每台设备只写自己的文件,读时合并,分叉留冲突副本 |
| 同步方式不带上存档 | 存档在 vault 里的普通文件夹;Obsidian Sync 在设置页提示打开"其他类型文件" |
| 存档文件被 iCloud 生成冲突副本 | iCloud 模式下把 `x 2.json` 当设备文件合并 |
| `LoadJson` 在剧本改过后就近定位、悄悄走错 | 续玩一律重放;不读旧状态(checkpoint 推迟,以后也只在剧本和配置都没变时用) |
| 重放把选项对错(同文字、改顺序、删选项) | 不用 `pathStringOnChoice`;只认唯一相同的原文,推测的标出来,对不上就停 |
| 选项都对上了,结果却变了 | 指纹只看掷骰和下一屏选项数,第一个差异处提示 |
| 重放停下截断长局、存档被覆盖 | pending 保留到玩家做出新动作;只有玩家动作写存档 |
| 重放冻住界面 | 异步重放、让出主线程、可以取消;总预算;面板可见才重放 |
| 种子恢复不了,重放结果每次不一样 | 固定的注入顺序和 `prepare` 钩子;没有种子变量时引擎用自己的种子 |
| 改了神谕配置,过去的答案变了 | 骰盘结果存进动作 |
| 手动设值重放时覆盖剧本的改动 | 加减记增量(`adjust`),只有直接输入才是 `set` |
| 实时日志被截、写重、丢块,和批注抢 | 只追加、按 `seq` 补写;编辑器开着时用 Editor API 插入 |
| 存档文件夹或日志触发重新编译 | 存档文件夹不当依赖;日志路径不许落在依赖里 |
| 主剧本改名后局失联 | 剧本 id 加对应表,`rename` 时更新 |
| 两套界面(面板、网页)的维护成本 | 每刀写明做哪边;核对逻辑写一份,单独打包给所有网页 |
| 新标签在旧版插件、旧导出网页里被当普通选项走 | CHANGELOG 写明需要的版本 |
| 角色卡写回引发重编译死循环 | 推迟到最后,前提写在 §4.11 |
| 版权和商标 | 内置内容原创;开放许可的署名;模板名避开商标 |
| 范围蔓延 | 守住原则;每刀先写验收再动手 |

# 桌游与跑团支持 PRD(单人优先)

接在 `game-engine-prd.md` 后面。那份做出来的是"带检定的游戏书引擎";这份要让作者能在 Obsidian 里移植或设计单人跑团和桌游 RPG,并把一局玩成一篇笔记。

## 1. 背景与目标

- 现状:游戏模式已经有检定、五档判定、技能、资源、队友、物品、`#needs`、特效、存档、网页导出、`check-ink` 全分支探索和随机跑。302 玩起来就是一个人在 Obsidian 里跑团,只是剧本是写死的。
- 目标:作者拿一本单人规则书或自己的设计,规则写进 `game.md`,表写在笔记里,流程用 ink 写,面板里能玩,网页能导出,`check-ink` 能跑平衡;玩家玩完一局,一键把这局写成笔记。
- 一句话:循环和剧本在 ink 里写,引擎不动;引擎只补 ink 做不了或做得难看的五样:自由骰、随机表、牌堆、玩家写字、日志。
- 沿用上一份 PRD 的非目标:不做通用 RPG 框架。系统之间的差异用 `game.md` 的骰法加 ink 写出来,不做覆盖所有系统的规则 DSL。

## 2. 适用范围

一条判断标准:这个游戏能不能写成"读一段 → 选一个 → 掷骰或抽牌 → 改数值"的循环。

| 类型 | 适用 | 要什么 |
|---|---|---|
| 游戏书(翻段落、一两个属性、简单战斗) | 是,一段一个 knot | 自由骰;战斗循环用 ink 写 |
| 单人 TRPG 规则书(Ironsworn 这类:动作、进度条、神谕) | 是 | 随机表、神谕(就是带可能性等级的表)、进度条(就是资源) |
| 日志型(抽提示、掷骰、写一段) | 是,和 Obsidian 最配 | 玩家写字、日志、牌堆 |
| 自己设计的原型 | 是,最强的用法 | 以上全部,加 `check-ink` 的统计 |
| 手牌、二维地图 | 有限 | 牌区(4.6)、舞台地图(4.7);自由拖放、网格战斗不做 |
| 靠空间摆放取胜的(棋子怎么走、牌怎么摆) | 否 | 非目标 |

Inkwright 是文字流程引擎,不是桌面引擎。凡是"看一眼全局"的部分都得翻成 HUD 里的数字、牌区里的牌和地图上的记号;翻不过去的游戏不移植。

### 2.1 目标游戏

作者想玩的是诡镇奇谈(卡牌版)和魔法骑士这一类单人冒险桌游。两种代表:

- **诡镇式(牌驱动)**:调查员属性和资源、玩家牌库与手牌、遭遇牌库、地点与连接、线索和末日计数、场景/议程双线、混沌袋检定、一回合几个行动。够得着:检定、资源、牌堆、手牌都有;还差牌上的数字(费用、图标)、混沌袋这种检定规则、地点上的计数和未揭示的地点。
- **魔法骑士式(地图加结算)**:逐步揭开的地图、地形和移动费、牌带移动/攻击值、法力资源、敌人有护甲、分阶段战斗。原版的六角板块拼接和整套战斗结算不追;做同风格的小号版:地图逐步揭开、牌带数值、敌人有属性,规则用 ink 写。

买来的游戏只在 vault 里私下移植,当验收用;公开仓库和教程只用原创。

## 3. 核心体验

作者:规则在 `game.md`,表是笔记里的 markdown 表格,流程在 ink。改一个数,`check-ink --random 300` 跑三百局,看结局概率和资源范围。

玩家:面板里读、选、掷、抽、写。骰子和表的结果以卡片出现在正文里,和检定一样。一局结束,"写成笔记"把这局变成 vault 里的一篇日志。

## 4. 原语

全部沿用检定的做法:EXTERNAL 由引擎绑定,随机走同一个 run seed 加计数器(回退、读档、重放结果一致),`_engine.ink` 里带无引擎时的回退函数,状态留在 ink 里。

### 4.1 自由骰 `roll("2d6+3")`

- 语法 `NdM`,可带 `+K`/`-K`;`d100`;`d66`(两个 d6 拼十位个位)。取高取低、骰池之后再说。
- 返回整数。面板里显示骰子卡(骰面、总和),进骰子日志。
- 回退:返回均值取整。

### 4.2 随机表 `table("encounter")`

- 表来自两处:`game.md` 的 `tables:` 内联,或 vault 里一篇笔记的 markdown 表格(`from: 表/遭遇.md`)。第一列是范围(`1-3`、`4`、`66`),后面是文本;范围决定权重,没有范围列就均分。
- 返回文本。要按结果做逻辑的,表里加 id 列,`table_id("encounter")` 返回 id。
- 面板里显示"掷表"卡:骰值加命中的那一行。
- 回退:返回第一行。
- 神谕不单做:一张"可能性 × 骰值"的表就是神谕,写在教程里。

### 4.3 牌堆 `draw("clues")`

- 牌在 `game.md` 的 `decks:` 里定义(id、name、desc,都是 LocalizedText)。
- 生成的 ink 里每个牌堆一个 LIST 加一个"剩余"VAR;`draw` 从剩余里随机取一张并移出,`shuffle` 放回全部;手牌和弃牌用 ink 自己的 LIST 操作,不另做。
- HUD 显示每个牌堆剩几张。
- 回退:取剩余里的第一张。

### 4.4 玩家写字 `#input:var`

- 选项带这个标签,面板显示文本框;提交后文字写进那个 VAR(字符串),再走这个选项。网页导出一样。和出牌(4.6)走同一条路:带 payload 的选项,先写一个 VAR 再选。
- `explore` 填一个占位串。存档自然带着。
- 用处:起名、写誓言、日志型的"写一段"。

### 4.6 牌桌:手牌与出牌

牌堆(4.3)只管抽。打牌要的是:看得见手里的牌,点一张打出去,手机上也顺手。

- `game.md` 的 `hands:` 声明牌区:`[{ id: hand, name: { zh: 手牌, en: Hand } }]`。id 就是剧本里的 LIST 变量名(`VAR hand = ()`),加减还是剧本自己写;桌面上摊着的、弃掉的,各是一个变量一个牌区。
- 面板和网页在正文和选项之间画牌区:一张牌一张小卡(牌堆色、名字,选中后在下面显示 desc),横着一排;手机上横向滑动,点一下选中、再点取消。不拖拽,不长按,不翻面动画。没牌时牌区收成一行"手牌 0"。
- 出牌:选项带 `#play:hand`。没选牌时按钮灰着;选了一张,按钮变成"打出 · 字条",按下去引擎先把那张牌写进 `played`(生成的 `VAR played = ()`,InkNames `played/出牌`),再走这个选项。剧本里 `~ hand -= played`、`{played == note: …}`。一个选项顶一手牌的所有选项;哪些牌能打,由剧本判断(打错了说一句再回选项);牌区空时选项锁住,像 `#needs`。
- 选哪张牌是玩家的决定,不是随机:和选项序号一起记进 picks,回退、读档、换语言重放照旧。`explore` 把 `#play` 的选项按手里每张牌展开成一个 move;`--random` 随机选一张。日志写"打出:字条"。
- 实现上是"带 payload 的选项":`PlaySession.choose(index, payload?)`,payload = 先写一个 VAR 再选;`#input`(4.4)复用。
- 不做:拖拽、牌面图片、牌在桌上的位置、多人。

### 4.7 地图(舞台)

桌游模拟器那种二维桌面,Inkwright 自己画,手机也能用。按诡镇式剧本的需要定:

- `game.md` 里 `map:`:一张图(可选;没有图就画一块素板)和若干地点(id、name、坐标、`links` 相邻地点、`hidden` 起初未揭示、`counter` 显示哪个变量的数);`tokens` 是地图上的记号(id、name、color、起始地点)。
- 或者 `map: { from: 地图.canvas }`,用 Obsidian 的画布当编辑器:图片节点是底图,文本节点是地点(第一行是 id,`?` 开头表示起初未揭示),节点之间的连线是 `links`;`game.md` 里的 `places` 只补名字、计数这些。拖一拖就排好版。
- 状态全在 ink 里,和骰子、牌堆一个做法:引擎生成 `LIST places`、`VAR here`(玩家在哪)、`VAR revealed`(揭开了哪些)、每个记号一个 `VAR <id>_at`(空列表 = 不在图上);剧本自己 `~ here = study`、`~ revealed += hallway`、`~ ghoul_at = study`。存档、回退、换语言、探索都不用另起炉灶。
- 选项带 `#go:<place>`:地图上那个地点亮起来,点它就等于选这个选项;选项本身还是按钮。地点是不是相邻、能不能去,由剧本的条件决定,`links` 只管画线和提示。
- 面板在 HUD 下面画:图、线、地点(未揭示的画成问号)、记号、计数;导出网页把图转成 data URI 一起带走。
- 不做:网格、迷雾、自由拖放、板块随机拼接。

### 4.8 牌的属性,牌从笔记来

牌可以带数字字段(`cost: 2`、`icons: { combat: 1 }`,嵌套的拍平成 `icons_combat`)和一张图 `image`;引擎生成 `card_cost(card)` 这类函数给 ink 读,牌面上显示封面和角标。诡镇的费用和图标、魔法骑士的移动和攻击值都靠它。

牌堆可以 `from: 牌/手段/` 指向一个文件夹:一篇笔记一张牌,文件名是 id,frontmatter 是 name、desc、image 和属性,正文是说明。用 Bases 的卡片视图管牌库,Inkwright 只读。

### 4.9 面板视觉

牌面带封面和属性角标;地图记号可以用图;配色跟主题走。普通剧本模式不受影响。

### 4.10 混沌袋

第三种检定规则 `rules.kind: bag`:袋子是一列标记(`value` 修正值,`auto: fail|success` 自动失败/自动成功,`count` 放几个,`name` 玩家看到的名字),检定时抽一个放回,技能加修正加标记值比难度,`partialBelow` 给勉强档。检定卡片和掷骰记录显示抽到的标记,选项上的成功率按袋子算,无引擎时按袋子的平均值判。袋子是规则,一局之内不变。投入手牌加图标,先用 `#play` 一张张投,多选界面以后再说。

### 4.5 日志:"把这局写成笔记"

- 一条命令,把 `PlaySession` 的 log(段落、选的选项、骰子和表的卡、输入的文字)按 markdown 写进 vault 一篇笔记。
- 路径模板在 `game.md` 的 `journal:`,默认 `日志/{date} {story}.md`。
- 不改 ink,不改引擎,纯面板侧。

## 5. 内容格式

`game.md` 新字段:

```yaml
tables:
  - { id: encounter, name: { zh: 遭遇, en: Encounter }, from: 表/遭遇.md }
  - { id: oracle, name: { zh: 神谕, en: Oracle }, rows: [ { range: "1-2", zh: 不, en: No }, { range: "3-4", zh: 是,但, en: Yes, but }, { range: "5-6", zh: 是, en: Yes } ] }
decks:
  - { id: clues, name: { zh: 线索, en: Clues }, cards: [ { id: c1, name: { zh: 血手印, en: Bloody handprint } } ] }
journal: { path: "日志/{date} {story}.md" }
```

ink 里:

```ink
你掷出 {roll("1d6")}。
遭遇:{table("encounter")}。
~ temp c = draw("clues")
* [写下你的誓言 #input:vow]
```

## 6. 引擎功能

### 第一刀(已做)

自由骰、随机表(内联和笔记两种来源)、日志。理由:每个系统都要骰和表;日志不动 ink,成本最低,价值最高,是 Obsidian 独有的。

### 第二刀(已做)

牌堆加 HUD。

### 第三刀(已做)

牌桌(4.6):`hands`、`#play`、带 payload 的选项,面板、网页、`explore` 三处,教程一节。

### 第四刀(已做)

地图(4.7):图、地点、连接、未揭示、计数、记号,`#go`,面板和网页各画一张,教程一节。

### 第五刀(已做)

牌的属性与牌从笔记来(4.8)、Canvas 地图(4.7)、面板视觉(4.9)。

### 第五刀半(已做)

混沌袋(4.10),教程 8.6。

### 第六刀

验收:作者私下移植一个诡镇式剧本(vault 里,不公开),缺什么补什么;然后一个原创的诡镇式示例进教程。`check-ink` 加统计:每个资源的分布、每张表和每张牌的命中次数。

### 之后

玩家写字(4.4,复用 payload)、魔法骑士式的示例、战役层(跨剧本的角色笔记)、取高取低、骰池。

### 非目标

通用规则建模;自由拖放的桌面、网格战斗;多人;自动战斗;把私有规则书的文字抄进公开仓库。

## 7. 验收(第一刀)

- 一个 40 段以内的原创游戏书示例:一个属性、一个运气值、一张遭遇表、一个用 ink 写的战斗循环。面板能玩,网页导出能玩,`check-ink --all` 能跑。
- 回退、读档、重放之后,骰值和表的结果一样。
- "写成笔记"产出的 markdown 在 Obsidian 里直接能读,带骰子和表的结果。

## 8. 风险

- `explore` 和随机:自由骰和表不能像检定那样枚举两面。处理:走 seed,`--random N` 看分布。按表结果跳转的结构性分支会漏;文档里写明"结构性分支用检定或选项,别靠表"。
- 双语:表格多一列(zh、en),牌用 LocalizedText。
- 版权:示例和教程只用原创或开放许可的系统;文档写明买来的规则书只能私用。
- 范围蔓延:每移植一个系统都会想"再加一样"。守住五个原语,系统差异用 ink 写。

## 9. 里程碑

四刀各一个 PR,每个带测试、CHANGELOG、教程一节。先做第一刀。

## 10. 待定

- 表的双语列怎么排;笔记里的表按文件路径还是按标题引用。
- `roll` 默认显示卡,要不要一个不显示的版本。
- 日志记不记没选的选项;默认路径。
- 第一个示例游戏:原创(推荐),还是某个开放许可的系统。
- `#play` 只允许打部分牌:先靠剧本判断;不够用再加 `#play:hand:<条件变量>`。
